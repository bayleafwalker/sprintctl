# sprintctl pg backend and remote mode plan

Workstream B of `/projects/dev/agentops/docs/plans/agentops/agent-ops-substrate-plan.md`. Workstream A is assumed shipped: the `sprint-taken-up` / `sprint-released` event model and canonical payloads from `contracts.py` are the contract this pg backend must preserve exactly.

## Goal

Sprintctl gains a direct-postgres `remote` mode for multi-host coordination while preserving the current sqlite `local` mode, CLI surface, and event model.

## Scope

What changes in this workstream:

- New storage module: `sprintctl/pg.py`, independent from `sprintctl/db.py`.
- New backend resolver: small mode/env/repo-root helpers called from `cli.py` before opening storage.
- `cli.py` routes existing verbs to either sqlite local storage or pg remote storage, with no per-command backend flags.
- New env contract: `SPRINTCTL_BACKEND={local,remote}`, `SPRINTCTL_DB=<path>` for local, `SPRINTCTL_URL=<pg-url>` for remote.
- New repo marker: `.sprintctl/backend.json`, used to reject mode mismatch before any writes.
- New migration verb: `sprintctl migrate-to-remote`.
- New NDJSON export/import helpers for migration and tests.
- Pg schema migrations for sprint, track, work_item, event, and support tables required by existing verbs.
- Tests for repo_id resolution, mode mismatch, pg schema correctness, migration round-trip, and integration against real postgres.
- Appservice GitOps plan for a sprintctl CNPG cluster; sprintctl itself does not ship production Kubernetes manifests.

What does not change:

- No backend abstraction layer or plugin backend API.
- No API daemon in front of postgres.
- No local write queue, replay log, or offline remote mode.
- No auditctl, actionq, or cockpit integration beyond preserving the read shape they will need later.

## Pg Schema

The pg schema is a single schema with `repo_id text not null` on the core sprintctl tables. `repo_id` is always the repository directory name. The schema uses globally generated integer ids for CLI compatibility and also declares `(repo_id, id)` unique keys so child rows cannot cross repository boundaries.

Event payloads are stored as `jsonb`, but the JSON object is produced by the same `contracts.canonicalize_event_payload()` functions used by sqlite. There is no pg-specific payload shape.

```sql
CREATE TABLE IF NOT EXISTS schema_version (
    version integer NOT NULL
);

INSERT INTO schema_version(version)
SELECT 1
WHERE NOT EXISTS (SELECT 1 FROM schema_version);

CREATE TABLE IF NOT EXISTS sprint (
    repo_id    text        NOT NULL,
    id         bigint      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name       text        NOT NULL,
    goal       text        NOT NULL DEFAULT '',
    start_date date,
    end_date   date,
    status     text        NOT NULL DEFAULT 'planned'
                           CHECK (status IN ('active', 'closed', 'planned')),
    created_at timestamptz NOT NULL DEFAULT now(),
    kind       text        NOT NULL DEFAULT 'active_sprint'
                           CHECK (kind IN ('active_sprint', 'backlog', 'archive')),
    UNIQUE (repo_id, id)
);

CREATE TABLE IF NOT EXISTS track (
    repo_id     text        NOT NULL,
    id          bigint      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sprint_id   bigint      NOT NULL,
    name        text        NOT NULL,
    description text        NOT NULL DEFAULT '',
    created_at  timestamptz NOT NULL DEFAULT now(),
    UNIQUE (repo_id, id),
    UNIQUE (repo_id, sprint_id, name),
    FOREIGN KEY (repo_id, sprint_id)
        REFERENCES sprint(repo_id, id)
        ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS work_item (
    repo_id     text        NOT NULL,
    id          bigint      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    track_id    bigint      NOT NULL,
    sprint_id   bigint      NOT NULL,
    title       text        NOT NULL,
    description text        NOT NULL DEFAULT '',
    status      text        NOT NULL DEFAULT 'pending'
                            CHECK (status IN ('pending', 'active', 'done', 'blocked')),
    assignee    text,
    created_at  timestamptz NOT NULL DEFAULT now(),
    updated_at  timestamptz NOT NULL DEFAULT now(),
    UNIQUE (repo_id, id),
    FOREIGN KEY (repo_id, sprint_id)
        REFERENCES sprint(repo_id, id)
        ON DELETE CASCADE,
    FOREIGN KEY (repo_id, track_id)
        REFERENCES track(repo_id, id)
        ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS event (
    repo_id      text        NOT NULL,
    id           bigint      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sprint_id    bigint      NOT NULL,
    work_item_id bigint,
    source_type  text        NOT NULL
                             CHECK (source_type IN ('actor', 'daemon', 'system')),
    actor        text        NOT NULL,
    event_type   text        NOT NULL,
    payload      jsonb       NOT NULL DEFAULT '{}'::jsonb,
    created_at   timestamptz NOT NULL DEFAULT now(),
    UNIQUE (repo_id, id),
    FOREIGN KEY (repo_id, sprint_id)
        REFERENCES sprint(repo_id, id)
        ON DELETE CASCADE,
    FOREIGN KEY (repo_id, work_item_id)
        REFERENCES work_item(repo_id, id)
        ON DELETE SET NULL
);

CREATE TABLE IF NOT EXISTS claim (
    repo_id            text        NOT NULL,
    id                 bigint      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    work_item_id       bigint      NOT NULL,
    agent              text        NOT NULL,
    claim_type         text        NOT NULL DEFAULT 'execute'
                                      CHECK (claim_type IN ('inspect', 'execute', 'review', 'coordinate')),
    exclusive          boolean     NOT NULL DEFAULT true,
    created_at         timestamptz NOT NULL DEFAULT now(),
    expires_at         timestamptz NOT NULL,
    heartbeat          timestamptz NOT NULL DEFAULT now(),
    branch             text,
    worktree_path      text,
    commit_sha         text,
    pr_ref             text,
    claim_token        text,
    runtime_session_id text,
    instance_id        text,
    hostname           text,
    pid                integer,
    UNIQUE (repo_id, id),
    FOREIGN KEY (repo_id, work_item_id)
        REFERENCES work_item(repo_id, id)
        ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS ref (
    repo_id      text        NOT NULL,
    id           bigint      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    work_item_id bigint      NOT NULL,
    ref_type     text        NOT NULL DEFAULT 'other'
                              CHECK (ref_type IN ('pr', 'issue', 'doc', 'other')),
    url          text        NOT NULL,
    label        text        NOT NULL DEFAULT '',
    created_at   timestamptz NOT NULL DEFAULT now(),
    UNIQUE (repo_id, id),
    FOREIGN KEY (repo_id, work_item_id)
        REFERENCES work_item(repo_id, id)
        ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS dep (
    repo_id         text        NOT NULL,
    id              bigint      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    item_id         bigint      NOT NULL,
    blocked_item_id bigint      NOT NULL,
    created_at      timestamptz NOT NULL DEFAULT now(),
    UNIQUE (repo_id, id),
    UNIQUE (repo_id, item_id, blocked_item_id),
    FOREIGN KEY (repo_id, item_id)
        REFERENCES work_item(repo_id, id)
        ON DELETE CASCADE,
    FOREIGN KEY (repo_id, blocked_item_id)
        REFERENCES work_item(repo_id, id)
        ON DELETE CASCADE
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_claim_token
    ON claim(repo_id, claim_token)
    WHERE claim_token IS NOT NULL;

CREATE INDEX IF NOT EXISTS idx_sprint_repo_archived
    ON sprint(repo_id, status, kind, created_at DESC);

CREATE INDEX IF NOT EXISTS idx_event_repo_sprint_type_ts
    ON event(repo_id, sprint_id, event_type, created_at);

CREATE INDEX IF NOT EXISTS idx_work_item_repo_sprint_status
    ON work_item(repo_id, sprint_id, status);

CREATE INDEX IF NOT EXISTS idx_track_repo_sprint
    ON track(repo_id, sprint_id);

CREATE INDEX IF NOT EXISTS idx_claim_repo_item_expires
    ON claim(repo_id, work_item_id, expires_at);
```

`idx_sprint_repo_archived` intentionally uses current columns even though the substrate plan called it `(repo_id, archived_at)`: the current sprint schema has no `archived_at`. Cockpit's v1 active-sprint query should be `WHERE repo_id = ANY($1) AND status='active' AND kind='active_sprint' ORDER BY created_at DESC`.

Event types remain free text. The required Workstream A values are:

- `sprint-taken-up`
- `sprint-released`

Their payloads are exactly the canonical payloads documented in `sprintctl-multi-agent-takeup-plan.md`; pg only changes the physical JSON storage from sqlite text to `jsonb`.

## `repo_id` Resolution

Remote mode needs a repo identity before it can query pg. Resolution is path-derived and has no registry:

1. Start at `Path.cwd()` unless a command already has an explicit repo root argument in future code.
2. Walk upward looking for `.sprintctl/backend.json`.
3. If no backend marker exists, walk upward looking for `.sprintctl/sprintctl.db`.
4. If no sprintctl marker exists, walk upward looking for `.git`.
5. The repo root is the directory containing the first marker found.
6. `repo_id = repo_root.name`.

If no marker is found, local mode may still use `SPRINTCTL_DB` as today. Remote mode fails with:

```text
Error: cannot resolve repo_id for remote mode. Run from inside a repository with .sprintctl/backend.json or .git.
```

The backend marker is JSON so old and new code can inspect it without importing sprintctl:

```json
{
  "backend": "remote",
  "repo_id": "homelab-analytics",
  "created_at": "2026-04-26T00:00:00Z"
}
```

`repo_id` in the marker is a guard, not an override. If it differs from the resolved directory name, startup fails:

```text
Error: repo marker mismatch: marker repo_id='X' but directory name resolves to 'Y'.
```

## Mode Detection and Errors

Mode is explicit. There is no implicit remote fallback and no command-line backend flag.

Rules:

- `SPRINTCTL_BACKEND` missing: treat as `local` for backward compatibility.
- `SPRINTCTL_BACKEND=local`: require local sqlite behavior. `SPRINTCTL_DB` is optional and defaults exactly as today.
- `SPRINTCTL_BACKEND=remote`: require `SPRINTCTL_URL`.
- Any other `SPRINTCTL_BACKEND` value is an error.
- If `.sprintctl/backend.json` exists and disagrees with `SPRINTCTL_BACKEND`, fail before opening sqlite or pg.
- If `SPRINTCTL_BACKEND=remote` and pg is unreachable, fail. Do not write locally.

Error messages:

```text
Error: invalid SPRINTCTL_BACKEND='X'. Expected 'local' or 'remote'.
Error: SPRINTCTL_BACKEND=remote requires SPRINTCTL_URL.
Error: SPRINTCTL_BACKEND=local cannot be used in repo 'homelab-analytics'; repo marker requires remote.
Error: SPRINTCTL_BACKEND=remote cannot be used in repo 'sprintctl'; repo marker requires local.
Error: could not connect to postgres from SPRINTCTL_URL: <driver message>
```

Backward compatibility failure mode:

- Remote-pinned repos must keep `.sprintctl/backend.json` and must not leave a writable sqlite database at the old active path.
- During `migrate-to-remote`, the old sqlite file is renamed to `.sprintctl.db.frozen-<ts>`, and `.sprintctl/sprintctl.db` is replaced with a directory sentinel. Old pre-remote sprintctl versions trying to open the old sqlite path fail at sqlite startup instead of creating or mutating a local db.
- The repo `.envrc` must export `SPRINTCTL_BACKEND=remote` and `SPRINTCTL_URL`. It should also export `SPRINTCTL_DB=$PWD/.sprintctl/sprintctl.db` even though new remote mode ignores it; that path is the directory sentinel, so old pre-remote sprintctl fails instead of falling back to `~/.sprintctl/sprintctl.db`.

## New Storage Module

Use `sprintctl/pg.py`, not `sprintctl/backend/pg.py`, to match the current flat package shape.

`pg.py` provides pg versions of the storage functions that `cli.py` uses today:

- `get_connection(url: str) -> PgConn`
- `init_db(conn) -> None`
- `create_sprint`, `get_sprint`, `list_sprints`, `get_active_sprint`, `list_active_sprints`
- `get_or_create_track`, `list_tracks`, `get_track`
- `create_work_item`, `get_work_item`, `list_work_items`, `set_work_item_status`
- `create_event`, `list_events`, `list_events_limited`, `list_knowledge_candidates`
- claim, ref, dep, maintain, usage, next-work, handoff query helpers needed by existing CLI verbs
- `export_ndjson(conn, repo_id, out)`
- `import_ndjson(conn, repo_id, records, *, replace=False)`

Every public function takes `repo_id` explicitly or is closed over by a small repository-scoped connection wrapper. The preferred implementation shape is a `PgStore` dataclass:

```python
@dataclass
class PgStore:
    conn: psycopg.Connection
    repo_id: str
```

`cli.py` should not be rewritten around a generic store abstraction. It should resolve mode once in `_get_store(obj)`, then call either `_db` or `_pg` through small local branches. Keep the first pass mechanical and boring.

Use `psycopg[binary]` for the driver. It is small, mature, supports typed rows, and keeps the implementation close to the sqlite code.

## CLI Delta

All existing verbs work in both modes unless they are explicitly local recovery artifacts:

- `claim recover` remains local-only if it depends on local claim recovery files. In remote mode it should say:

```text
Error: claim recovery files are local-mode only. Use pg claim state or an explicit claim token.
```

- Existing read/write verbs do not gain backend flags.
- Existing JSON output shapes remain stable.

New verb:

```text
sprintctl migrate-to-remote --url TEXT [--db PATH] [--repo-root PATH] [--repo-id TEXT]
                            [--dry-run] [--replace] [--keep-ndjson PATH]
                            [--yes] [--json]
```

Flags:

- `--url TEXT`: postgres URL. Defaults to `SPRINTCTL_URL`; required if env is absent.
- `--db PATH`: sqlite source. Defaults to `SPRINTCTL_DB`, then `<repo-root>/.sprintctl/sprintctl.db`, then current `db.get_db_path()`.
- `--repo-root PATH`: root for marker and repo_id resolution. Defaults to marker traversal from cwd.
- `--repo-id TEXT`: optional assertion. If supplied, must equal the path-derived repo id.
- `--dry-run`: open sqlite, export NDJSON, validate pg connectivity and schema, but do not import or rename.
- `--replace`: delete existing rows for `repo_id` in pg inside the import transaction before importing. Required when pg already has rows for the repo.
- `--keep-ndjson PATH`: write the migration stream to a file for review/debug.
- `--yes`: skip interactive confirmation before freezing sqlite.
- `--json`: emit machine-readable summary.

Text success output:

```text
Migrated repo 'homelab-analytics' to remote postgres.
Imported: 3 sprints, 8 tracks, 41 items, 129 events, 6 claims, 14 refs, 5 deps.
Frozen sqlite: /projects/dev/homelab-analytics/.sprintctl/.sprintctl.db.frozen-20260426T153012Z
```

Error cases:

- Source sqlite missing: `Error: sqlite source not found: <path>`
- Source sqlite not at latest local schema after `init_db`: `Error: local migration failed before export: <message>`
- Pg schema missing: `Error: remote schema is not initialized. Run sprintctl remote-migrate first.`
- Existing pg rows without `--replace`: `Error: remote repo_id 'X' already has data. Use --replace to re-import intentionally.`
- Import fails: leave sqlite untouched and keep any NDJSON artifact requested.
- Freeze/marker creation fails after import: print exact rollback instructions and leave pg import committed.

## CNPG Cluster Answer

Sprintctl gets its own CNPG cluster, not a schema or database inside `actionq-cnpg-main`.

Concrete shape:

- Namespace: `vscode`
- Cluster: `sprintctl-cnpg-main`
- Database: `sprintctl`
- Owner/user: `sprintctl`
- Instances: `1`
- Storage: `1Gi` Longhorn to start, same as actionq
- Secret: CNPG-generated `sprintctl-cnpg-main-app`
- NetworkPolicy: allow CNPG operator status/instance traffic and allow postgres ingress from `vscode-shell` pods

Rationale:

- **Schema isolation**: sprintctl is durable coordination state across repos. Actionq is queue/dispatcher state. Separate clusters keep lifecycle, restore drills, and accidental destructive operations separate.
- **Backup story**: a future CNPG backup policy can restore sprintctl without restoring actionq dispatch experiments. Until backups are enabled for this small cluster, the migration NDJSON and frozen sqlite are still rollback artifacts.
- **Connection auth distribution**: CNPG's generated app secret maps cleanly to `SPRINTCTL_URL`, mirroring `ACTIONQ_URL` without sharing credentials.
- **Operational cost**: single-instance CNPG is already the accepted shape for actionq smoke state; duplicating that pattern is simpler than inventing multi-database ownership in one cluster.

## Auth Distribution Answer

Devbox:

- Appservice injects `SPRINTCTL_URL` into the `vscode-shell` deployment from `secretKeyRef: sprintctl-cnpg-main-app / uri`.
- `vscode-shell` writes `/etc/profile.d/sprintctl-remote.sh` the same way it currently writes `ACTIONQ_URL`.
- Remote-pinned repo `.envrc` exports `SPRINTCTL_BACKEND=remote`, sets `SPRINTCTL_DB` to the sentinel path for old-client failure, and relies on the injected `SPRINTCTL_URL`.

Workstation:

- Preferred v1 path: `kubectl port-forward` through the appservice kubeconfig, because it reuses existing cluster auth and does not expose postgres on the LAN.
- Workstation helper convention:

```bash
direnv exec /projects/dev/appservice \
  kubectl -n vscode port-forward svc/sprintctl-cnpg-main-rw 15432:5432
export SPRINTCTL_URL='postgresql://sprintctl:<password>@127.0.0.1:15432/sprintctl'
```

- Password retrieval is operator-controlled from the CNPG-generated secret:

```bash
direnv exec /projects/dev/appservice \
  kubectl -n vscode get secret sprintctl-cnpg-main-app -o jsonpath='{.data.uri}' | base64 -d
```

Rejected for v1:

- NodePort: too much exposure for direct database access.
- Tailscale database exposure: useful later if port-forward becomes annoying, but it requires a separate auth and routing decision.
- Copying a long-lived plaintext URL into the sprintctl repo: credentials do not belong in repo files.

## `migrate-to-remote` Implementation

Migration has four phases.

1. Preflight:

- Resolve `repo_root` and `repo_id`.
- Open local sqlite source and run `db.init_db(conn)` so old supported schemas are upgraded before export.
- Connect to pg and run/verify `pg.init_db(conn)`.
- Check pg has no rows for `repo_id`, unless `--replace`.

2. Export:

- Emit NDJSON records in dependency order: `sprint`, `track`, `work_item`, `event`, `claim`, `ref`, `dep`.
- Each line has:

```json
{"table":"event","repo_id":"homelab-analytics","data":{...}}
```

- Preserve sqlite integer ids exactly during import with `OVERRIDING SYSTEM VALUE`; advance pg identity sequences after import.
- Preserve sqlite timestamp strings by parsing as UTC.
- Canonicalize each event payload during export, then assert the canonicalized object is unchanged during import.

3. Import:

- Use one pg transaction for the whole repo import.
- If `--replace`, delete rows for `repo_id` in dependency-safe order inside the same transaction.
- Insert with explicit ids.
- Verify row counts and representative hash totals after import.
- Commit only after all tables and constraints pass.

4. Freeze local:

- Rename source sqlite to `.sprintctl/.sprintctl.db.frozen-<YYYYMMDDTHHMMSSZ>`.
- Create `.sprintctl/backend.json`.
- Create the directory sentinel `.sprintctl/sprintctl.db/` to make old sqlite clients fail.
- Print a summary.

Idempotency:

- If import fails before commit, pg has no partial rows.
- If import succeeds but freeze fails, rerunning without `--replace` refuses because pg now has data. The error should tell the operator to either complete marker/freeze manually or rerun with `--replace`.
- If freeze succeeds, rerunning migration fails because source sqlite no longer exists at the active path and repo is already remote-pinned.

Rollback:

- Local rollback is explicit: remove `.sprintctl/backend.json`, remove the `.sprintctl/sprintctl.db` directory sentinel, move the frozen sqlite file back to `.sprintctl/sprintctl.db`, and set `SPRINTCTL_BACKEND=local`.
- Pg rollback for a repo is `DELETE FROM ... WHERE repo_id = $1` in dependency order, exposed only as a documented operator SQL snippet or a guarded test helper, not as a casual CLI command in v1.

## Migration Test Fixtures

Minimum fixtures that must round-trip cleanly through NDJSON export/import:

- Empty sqlite database at latest schema.
- Single closed sprint with no items.
- Active sprint with tracks, pending/active/done/blocked items, claims, refs, and deps.
- Database at the oldest supported sqlite schema version, then upgraded by `db.init_db()` during migration.
- Database with Workstream A takeup events: one active takeup, one released takeup, one release without prior takeup.

Round-trip means:

- Row counts match per table.
- Primary ids are preserved.
- Foreign-key relationships are preserved.
- Event payload JSON after pg read equals the canonical sqlite payload.
- Existing CLI read commands return equivalent JSON in local mode before migration and remote mode after migration.

## Test Plan

Unit tests:

- `tests/test_backend_mode.py`: env parsing, invalid backend values, missing `SPRINTCTL_URL`, marker mismatch errors.
- `tests/test_repo_id.py`: marker traversal, `.git` fallback, path-derived repo_id, marker repo_id mismatch.
- `tests/test_pg_schema.py`: DDL contains required repo_id columns, constraints, and indexes; can initialize an empty pg schema.
- `tests/test_migrate_to_remote.py`: fixture exports, imports, id preservation, frozen sqlite rename behavior, old-client sentinel creation.
- `tests/test_takeup_pg_contract.py`: `sprint-taken-up` and `sprint-released` payloads survive sqlite -> NDJSON -> pg unchanged.

Integration tests:

- Marked `pytest -m pg`, skipped unless `SPRINTCTL_TEST_PG_URL` is set.
- Run against a disposable schema or database, never the production `sprintctl` database.
- Exercise create/list/show/item/claim/event/takeup flows in remote mode.
- Exercise pg-unreachable error by pointing `SPRINTCTL_URL` at a closed localhost port.
- Exercise two `repo_id` values in the same schema and assert queries are isolated by repo.

Manual pilot verification:

cd /projects/dev/homelab-analytics

## Out Of Scope

- Auditctl schema, NDJSON audit shards, and audit publishers.
- Actionq daemon, actionq cluster service, queue state, and session lifecycle.
- Cockpit frontend and cross-source UI behavior.
- Pg API daemon.
- Multi-instance CNPG, poolers, and LAN-exposed postgres.

## Implementation Order

1. **Mode and repo marker preflight.** Add backend/env parsing, repo marker traversal, hard mismatch errors, and tests. Local mode remains the only working backend. Shippable because it adds safety before remote writes exist.

2. **Pg schema and connection module.** Add `sprintctl/pg.py` with connection handling, `init_db`, DDL, and simple sprint/track/item/event CRUD. Integration tests run against `SPRINTCTL_TEST_PG_URL`.

3. **CLI read/write routing for core verbs.** Wire sprint, item, event, render, usage, and maintain read paths to pg. Keep claim recovery local-only with an explicit remote error.

4. **Claims, refs, deps, and Workstream A takeup parity.** Fill in the remaining storage functions so existing coordination verbs work in remote mode. Add contract tests proving takeup payloads match sqlite.

5. **NDJSON export/import.** Implement deterministic export/import helpers and migration fixtures. No active repo migration yet.

6. **`migrate-to-remote` verb.** Add preflight, import transaction, freeze artifact, backend marker, directory sentinel, dry-run, JSON output, and rollback messaging.

7. **Appservice GitOps manifests.** In the appservice repo, add `clusters/main/kubernetes/apps/sprintctl-db` following `actionq-db`: CNPG cluster, kustomization, and network policy. Update `vscode-shell` to inject `SPRINTCTL_URL` from `sprintctl-cnpg-main-app`.

8. **Pilot homelab-analytics.** Run migration, compare local/remote command JSON, freeze sqlite, and pin `.envrc` to remote. Leave financial-analytics extension and sprintctl itself for later rollout steps from the substrate plan.

Steps 1-4 make remote mode functionally usable. Steps 5-6 make migration safe. Steps 7-8 put it into the actual cluster and prove the path with one repo.
